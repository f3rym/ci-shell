# ci-shell

**Не «запусти CI локально». А «верни меня в упавший прогон».**

Пайплайн упал. Контейнер, где это случилось, уже удалён — у тебя остался только лог.
Одна команда, и ты внутри того самого прогона: тот же образ, те же переменные,
тот же коммит, курсор на упавшем шаге.

```
$ ci shell https://gitlab.com/acme/app/-/jobs/355442655

  джоба tests #355442655 упала
  тяну образ python:3.9… готово
  код на коммите a1b2c3d… готово
  проставляю окружение… 42 переменные
  выполнено 14 из 15 шагов, стою перед упавшим

  root@job:/builds/acme/app$ _
```

## Зачем

Знакомый цикл: правишь строчку → `git commit -m "fix ci"` → пуш → ждёшь десять минут →
читаешь лог → гадаешь снова. Пять итераций — час жизни и гирлянда мусорных коммитов.

Внутри шелла тот же вопрос решается за секунды:

```
root@job:/builds/acme/app$ echo $DATABASE_URL      # ага, пустая
root@job:/builds/acme/app$ python --version        # 3.9, а локально 3.12
root@job:/builds/acme/app$ pytest tests/test_x.py  # повторил падение за две секунды
```

## Чем отличается от act / gitlab-ci-local

|                          | act, gitlab-ci-local | ci-shell |
|--------------------------|----------------------|----------|
| Отправная точка          | yml-конфиг           | конкретный упавший прогон |
| Переменные               | из конфига           | того самого запуска |
| Поведение                | прогнать всё с нуля  | остановиться на упавшем шаге |
| Эмулирует движок CI      | да                   | нет — восстанавливает состояние |

Последняя строка главная: мы не эмулируем семантику CI, мы восстанавливаем
состояние одного конкретного прогона. Поэтому «тот же контейнер» — буквально.

## Установка

Нужны Go 1.26+ и Docker (или Apple `container` на macOS).

```bash
git clone https://github.com/f3rym/ci-shell && cd ci-shell
make build          # бинарь ./ci под твою систему
```

Кросс-сборки: `make macos`, `make linux`, `make windows`,
`make macos-container` — вариант для macOS, который зовёт Apple `container` вместо Docker.

## Использование

```bash
export GITLAB_TOKEN=glpat-...    # или CI_SHELL_TOKEN, или конфиг-файл по хостам
ci shell <ссылка на джобу>
```

Токены по хостам — в `~/.config/ci-shell/config` (права 0600, утилита проверит).

Маскированные переменные GitLab не отдаёт по API никому и никогда. Для них есть
локальный файл `~/.config/ci-shell/secrets.yml`: заполняешь один раз, утилита
подхватывает и честно перечисляет, чего не хватает. Твои секреты не покидают
твою машину — это не костыль, это позиция.

## Что умеет сейчас (v0.1.0)

- GitLab, docker-executor, джоба по ссылке
- Тот же образ, код на коммите джобы (git worktree), `CI_*` + переменные проекта и группы
- Прогон `before_script`/`script` до упавшего шага, дальше — интерактивный шелл
- Внятные ошибки вместо притворства: shell-executor и самописные ранеры не
  воспроизводятся в принципе — утилита так и скажет

В планах: автоопределение упавшей джобы без аргумента, артефакты предыдущих
стадий, `services`, `ci rerun` / `ci diff`, GitHub Actions.

## Ограничения, о которых честно

- Кэш ранера живёт на ранере — его нет. Distributed cache в S3 — в планах.
- Первый запуск с тяжёлым образом — это `docker pull`, наберись терпения.
  Дальше образ берётся из локального кэша.
- `include`/`extends` в конфиге пока разворачиваются не полностью — утилита
  скажет об этом явно, а не подсунет неверный конфиг.
